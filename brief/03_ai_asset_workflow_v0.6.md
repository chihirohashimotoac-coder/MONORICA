# 画像・音楽のAI制作と受け渡し v0.6

目的：既存のChatGPT Plus・Claude Pro・Suno Proを活用し、素材購入や外注をせず、全体の絵柄と音楽をそろえる。
以下の素材寸法・曲数・命名は初期案。ゲームへ取り込む前に少数で検証する。

## 1. 担当

| 担当 | 作業 |
|---|---|
| ChatGPT | モンスター、人物、タイル原画、背景、小物、イラストの生成・修正 |
| Suno Pro | オリジナルのBGM生成 |
| Claude Code | 素材仕様と生成指示、ファイル管理、寸法・透過・配置の調整、タイル化・取り込み、音声ループ設定、検証 |
| ユーザー | 未接続のアプリへの指示の受け渡し、候補の選択、ファイルのダウンロード・配置 |

画像を生成できることと、Claude CodeからChatGPTの画面を直接操作できることは別。
実際に接続された機能がなければ、指示文と必要ファイルの一覧を作り、ユーザーが受け渡す。
ChatGPTの利用枠を超えた場合も、別料金の画像APIへ自動的に切り替えない。

## 2. アートの基準

- 採用方向は、2Dドット絵の、真上に近い見下ろし型。
- フィールドの基準画像はfield_topdown_concept_v0.1.png。
- モンスター造形の最新候補はstarter_concepts_v0.4.png。最近のポケモンの全種確認から整理した、固有の輪郭、性格、行動を説明する器官、進化の変化を設計へ使う。
- starter_concepts_v0.4.pngは、初期形・最終形と3系列の造形の基準として採用した。採用原画は維持し、同じ方向の前・後・アイコンをドット絵へ展開する。ゲーム用素材の仕上げはこれから。
- 初期形はかわいさ、進化後は成長と親しみやすさの両方を表現する。顔や模様の密度を小さい表示サイズに合わせる。
- 道の縦横、建物正面の下向き、樹木・屋根・段差の重なりをそろえる。
- 基準画像の町・人物・生物の固有デザインは仮。正式な種族・人物とは区別する。
- 初期の比較画像field_art_comparison_v0.1.pngの上段3D案は採用しない。
- 画面全体の一枚絵と、動くゲームのタイル・キャラクターは別工程で制作する。
- AI出力のピクセル間隔、解像度、フレーム寸法は生成後に検査する。見た目がドットでも、使用可能な規格に合うとは限らない。
- 文字・ボタンはゲームのUI側で描く。素材画像に読めない文字を含めない。

### 初期の規格案

| 素材 | 提案規格 | 確認点 |
|---|---|---|
| 地形タイル | 論理32×32 px | 隣接・繰り返し、衝突形状、段差 |
| 人物 | 論理32×48 px、4方向×3フレームから試作 | 足元、頭身、向き、歩幅、透過 |
| 戦闘モンスター | 論理96×96 pxを基準、前・後の姿 | 足元基準、シルエット、対戦時の読みやすさ |
| メニューアイコン | 論理32×32 pxを基準 | 小さくても種族を区別できる |
| バトル動作 | 待機の少数フレーム＋移動・変形・技エフェクト | 個体の形を崩さず、演出省略でも結果が同じ |
| イベント連れ歩き | 必要な種だけ人物規格に合わせて制作 | 全150種分を初期必須にしない |

上記はゲームに取り込む論理サイズ。生成サービスの出力サイズとは別。
原画を十分な大きさで生成し、輪郭・色・透明度を確認してから規格に合わせる方法も使う。
高解像度画像を縮小しただけで合格とせず、実際の画面サイズで読む。

## 3. 制作順序

1. 最初の街の小さなタイルセット、主人公1種、相棒1種の前・後・アイコンを試す。
2. 実際のゲーム画面に配置し、画面密度、文字、ボタン、歩行、戦闘を確認する。
3. 色・輪郭・寸法・影・視点をART_BIBLEへ記録する。
4. 最初の相棒3系列と試作地域の必要素材を作る。
5. 種族データと素材manifestを対応させ、地域・進化系列単位で増やす。
6. 完成版で全種の前・後・アイコン、地域地形、人物、必要演出の欠落を検査する。

同じ基準画像を添付し、個体ごとの変更点だけを指定する。
進化前後は、色・耳・葉・模様などの共通要素を残し、体格・役割・シルエットで成長を伝える。
色違いは同じ種の差分として管理し、図鑑の種数とは分ける。

## 4. Claude Codeから素材生成へ渡す発注形式

各回、次の項目を一組にする。

~~~text
素材ID：
用途：
種族・人物の確定設定：
基準画像：
生成する向き・状態：
必ず維持する特徴：
今回変更する特徴：
背景と透明度：
生成原画のサイズ：
最終取り込み時の論理サイズ：
フレーム数・並び・余白：
保存先とファイル名：
合格条件：
~~~

まだ決まっていない種族設定を、生成時だけ勝手に確定しない。
最初は候補を少数比較し、選んだデザインを版管理してから増やす。

## 5. ChatGPT用：モンスター原画の指示テンプレート

~~~text
オリジナルのモンスター育成RPGに使う、1体の戦闘用ドット絵を制作してください。
添付の採用済みモンスター原画を、顔・シルエット・配色・固有の特徴の基準にしてください。
最近のポケモンに通じる親しみやすさを目指し、この種固有の顔・輪郭・器官・動作を保ちます。目・口・表情を他種と同じテンプレートへそろえず、性格に合う形を使ってください。
この原画の造形を、整理されたドット絵へ落とし込んでください。

素材ID：［ID］
種族設定：［動物・植物モチーフ、属性、性格、体格、成長段階］
固有の特徴：［必ず残す3点］
向き：［相手側の正面寄り／味方側の後ろ姿］
構図：全身、足元基準を統一、余白あり、他の個体なし。
ポーズ：［待機姿勢］
背景：本当の透明背景。接地影が必要な場合は別素材。
文字、ロゴ、UI、台座、背景の景色は含めないでください。

最終的には［96×96等］の論理ピクセル枠へ取り込みます。
そのサイズで形と特徴を読み取れる、整理されたシルエットにしてください。
最近のポケモンを参考とした親しみやすい造形で、この設定のオリジナル生物として仕上げてください。
~~~

後ろ姿は同じ種の正面画像を参照として添付し、顔の構造、色、模様、肢の数を維持する。
複数フレームを作るときは、全フレームで大きさ・足元・特徴を維持する。

### このテンプレートの評価ケース：未実行

1. 通常系：小型の四足動物で、前・後・アイコンが同一種と分かる。
2. 境界系：角・翼・長い尾がある種でも、枠外にはみ出さず他種と縮尺が破綻しない。
3. 失敗系：余分な肢、透明風の市松背景、絵柄のずれが出たら、その素材を採用せず必要部分を修正する。

## 6. ChatGPT用：地形・建物素材の指示テンプレート

~~~text
オリジナルRPGの、真上に近い見下ろし型2Dドット絵素材を制作してください。
添付のfield_topdown_concept_v0.1.pngを、配色とカメラの基準にしてください。

今回必要な素材：［草、土の道、岸、水面、木、家など、少数を具体的に列挙］
街の特徴：［地方の気候・暮らし・材質］
建物正面は画面下向き。道とタイルは画面の縦横に沿わせます。
屋根と木の上部が見え、前面の壁は短めです。奥行きは描かれた段差と重なりで表現します。
空や地平線を含めず、近景のタイルマップに使える素材にしてください。
人物・モンスター・文字・UI・影が焼き込まれた看板は含めません。

タイルの論理単位：［32×32等］
必要な接続：［上下左右、内角、外角、岸との境界など］
各パーツの並びと余白：［明示］
透明背景が必要なパーツ：［木や建物の上層など］
~~~

AIが規格どおりのタイル配置や継ぎ目を出せたか検査する。
切り出し・整列・色の統一を行い、隣接テスト用マップで確認する。
地形の見た目と衝突、上層の屋根・樹木による隠れ方を別データにする。

### このテンプレートの評価ケース：未実行

1. 通常系：草と道を敷き詰めても継ぎ目が目立たず、人物の縮尺が合う。
2. 境界系：岸の角、橋の両端、段差、建物の裏で見た目と通行判定が一致する。
3. 失敗系：遠近感や光源が違うパーツ、人物の描き込み、ぼけたタイルは修正後に再検査する。

## 7. Suno Pro用：BGMの基準

電子音のメロディと、柔らかい楽器音を組み合わせる。
最初に故郷・道中・通常戦闘の3曲で音色の方向をそろえ、テーマの短い共通モチーフを決める。
そのモチーフをライバル・終盤・結末でアレンジする案。
既存曲や特定作曲家の再現を指示しない。

曲数はマップ数と演出を見て決める。序盤では3曲、本編では20～30曲を初期案にし、必要性と契約内の利用枠で調整する。
完全なループを生成だけで保証せず、ダウンロード後にループ開始・終了を設定して試聴する。
音量差、冒頭の無音、ループのクリック、短時間で疲れる帯域を確認する。
ブラウザで再生できる圧縮形式を実機確認し、必要なら代替形式も用意する。

### 故郷・拠点

~~~text
Instrumental original soundtrack for a top-down pixel-art creature-adventure RPG.
Warm home village, late-summer greenery, friendship and the excitement of departure.
Handheld-era electronic lead melody, soft woodwinds, gentle plucked instruments,
warm bass and restrained percussion. A memorable short melodic motif.
Bright and comforting, with a hint of nostalgia. No vocals or spoken words.
Steady gentle tempo, suitable for repeated background listening.
Create a repeatable main section with a clean transition for a game music loop.
~~~

### 通常戦闘

~~~text
Instrumental original turn-based battle soundtrack for a pixel-art creature-adventure RPG.
Energetic but friendly competition, clever decisions and growing confidence.
Handheld-era electronic leads, punchy bass, brisk drums and short orchestral accents.
Clear memorable melody, forward momentum, no long ambient opening.
No vocals or spoken words. Avoid a final victory cadence inside the repeatable section.
Create a coherent repeatable section suitable for continuous game battles.
~~~

### ライバル

~~~text
Instrumental original rival battle theme for a story-focused creature-adventure RPG.
A childhood friend determined to win, ambition, tension and friendship underneath.
Handheld-era electronic lead, driving bass, urgent percussion and warm melodic counterpoint.
Use the attached original home-theme reference only if supported and available,
preserving a short recognizable friendship motif while increasing tension.
Competitive and emotionally charged, with hope rather than tragedy.
No vocals or spoken words. Repeatable main section for a turn-based battle.
~~~

参照音源を使えない環境では、添付したと説明せず、文章で音色・テンポ・モチーフの関係を指定する。

### 各BGM指示に共通の評価ケース：未実行

1. 通常系：目的の場面でループ試聴し、歌声がなく、会話・効果音を邪魔しない。
2. 境界系：戦闘終了直後の場面移動、消音、アプリ復帰でも多重再生せず、ループにクリックがない。
3. 失敗系：歌声、長い無音、途中の不自然な終止、極端な音量差があれば、編集・再生成して採用を見直す。

## 8. manifestとファイル管理

原画、ゲーム用書き出し、採用しなかった候補を分ける。
種族や地域の安定したIDでファイルを管理し、名前を変えてもセーブ参照を壊さない。
manifestには以下を保存する。

~~~text
assetId / speciesId・mapId / 用途 / 採用状態
制作サービス / 生成・ダウンロード時のプランと日時
指示文の保存先 / 参照画像 / 親バージョン / 変更内容
原画ファイル / ゲーム用ファイル / サイズ / 透過
フレーム配置 / 足元基準 / パレット / ループ開始終了
ゲーム内での確認結果 / 要修正点
~~~

Sunoでは正規のダウンロード手段で取得し、制作・取得時のプランを記録する。
利用枠・提供機能・利用条件が変わった場合は、制作時点の公式案内を確認する。

## 11. 全種確認後の設計手順

[デザイン調査](05_pokemon_design_research_v0.3.md)を読み、各種の主題、性格、動作、主要な器官、初期・中間・最終の輪郭を文章と小図で決めてから原画を作る。
色だけが違う似た形、全員同じ顔、初期形を拡大しただけの最終形を避ける方向で比較する。例外を使う場合も、その種の発想と成長の目的を説明する。
縮小時の識別、前後の一致、アニメーション化のしやすさは、ゲーム用素材を作った段階で実測・目視確認する。

変更履歴：v0.3 全種の図像確認を受け、顔のかわいさを一律化する指示から、輪郭・行動・器官・進化の関係へ重心を移した。
