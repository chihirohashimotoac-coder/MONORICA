# 素材先行・GitHub・Claude Codeクラウドでの制作手順 v0.1

## 方針の更新

ユーザーはClaude Codeのクラウド環境で開発し、GitHubに資料・素材データを用意してから実装する方法を希望している。
今後はこの進め方を前提にする。旧資料の「Windowsで専用フォルダを開いて、今すぐ村の実装から始める」という手順より、この文書を優先する。
素材を先にそろえる場合も、量産前に少数で規格を検証する工程を入れる案とする。

## 推奨する順序

1. 本編とクリア後を含むコンテンツ一覧・必要素材一覧を作る。150種以上の系統図、人物、地域、イベント、技、道具、BGM、UIまで対象にする。
2. 画像・音声・JSONの規格を決める。まず人物1種、地形一組、モンスター1種の前後・アイコン、音楽1曲で表示・切り出し・透過・接続・ループを確認する。
3. 確認した規格で全体の素材とデータを制作する。地域や進化系列ごとに完成状況を台帳へ記録し、必要に応じてGitHubにも順次登録する。
4. 素材とデータを照合する。未制作、提案、採用原画、取り込み可能、確認済みを区別し、必要な参照先をそろえる。
5. 一式をGitHubへ登録し、Claude Codeクラウドに対象リポジトリを指定して本格実装を依頼する。
6. 実装で見つかった表示・操作・バランスの問題を修正する。素材先行でも、数値調整や一部素材の修正は想定する。

第2段階の検証は、ゲーム本体とは別の小さな素材確認用画面でも行える。
このチャットで準備して確認し、その後に全素材をそろえてClaude Codeへ渡す進め方を採れる。
画像の寸法・足元・向き・余白が未確定のまま150種以上を仕上げると、規格の変更時に広い範囲の修正が必要になるため、少数の確認を先に行う。

## 先にそろえるデータと、実装後にも調整する項目

| 対象 | 素材制作で用意するもの | 実装後にも確認するもの |
|---|---|---|
| モンスター | 全種と系統図、安定ID、属性、技、進化条件、図鑑、入手経路、前後・アイコン | 表示サイズ、技の威力、成長速度、編成の強さ |
| 人物 | 主人公・ライバル・NPCの設定、歩行素材、必要な表情 | 当たり判定、移動の速さ、演出の間 |
| マップ | 地域のつながり、地形・建物・小物、配置案、衝突・接続情報 | 歩いて迷わないか、探索の長さ、移動とイベントの干渉 |
| 物語 | 章、会話、分岐、イベントID、フラグ、再挑戦経路 | 中断後の復帰、進行順の例外、所要時間 |
| 音 | BGM・効果音、使用場面、取り込み用ファイル、ループの指定 | 音量、切り替え、実際のループ、スマートフォンでの再生 |
| UI | アイコン、ウィンドウの規則、画面案、表示文言 | 読みやすさ、タッチの大きさ、画面比率への対応 |

本編20～30時間・主要やりこみ込み約50時間は、素材をそろえただけでは検証できない。実際に遊んで測る。
個体値・技の威力・報酬などは機械可読データとして先に用意し、変更しやすい形にする。

現在あるのは採用原画・企画資料・試作用の相性表が中心。

## GitHubへ登録する構成案

```text
README.md
CLAUDE.md
START_CLAUDE_CLOUD.txt
brief/                   これまでの企画・原画・生成指示と、最新のクラウド用指示
docs/                    素材規格、素材台帳、進行手順
content/                 種族・技・進化・相性・遭遇・イベントのJSON
assets/source/           生成原画・編集元
assets/runtime/          ゲームへ取り込む画像・音声
manifests/assets.json     実ファイル、ID、用途、制作状態
tools/validate_assets.py  台帳と実ファイルの照合
```

ZIPは受け渡し用。GitHubへは展開したファイル構成で登録し、Claudeが各ファイルを直接参照できる形にする。
最初から全ての元音声や巨大な編集ファイルを含めず、原本の保管先とゲームに必要な取り込み用ファイルを整理する。
現在のクラウド準備パックには参照用原画がbriefに入っている。assets/sourceとassets/runtimeは今後の制作用の置き場で、未制作素材を配置済みとはしていない。

## クラウド用設定とプラグイン

Claude CodeクラウドはGitHubのリポジトリを使って作業する。[公式のクラウド作業案内](https://code.claude.com/docs/en/claude-code-on-the-web)。
リポジトリのCLAUDE.mdやプロジェクト内のSkillはクラウドへ持ち込める一方、PCだけに入れた設定やプラグインの引き継ぎ、リポジトリ設定によるプラグインの自動インストールは前提にしない。[公式の持ち込み設定一覧](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup)。
必要な指示はまずCLAUDE.mdと仕様書に保存し、追加ツールは実際のクラウド環境で使えることを確認する。

GitHubの通常のGitでは1ファイル100MiBを超えるファイルが制限され、ブラウザ追加は1ファイル25MiBが上限。[GitHub公式のファイル制限](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。
画像・音声の実容量を確認してから、大きな原本の保管やGit LFSの採用を決める。追加予算0円の条件を守り、保存・転送の追加課金を前提にしない。

クラウドで制作しても、完成ゲームのセーブ先は従来の要件どおりプレイヤー端末内とする。
