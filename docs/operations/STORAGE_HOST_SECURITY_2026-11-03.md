# ダウンロード先ホストのセキュリティ確認

確認日：2026-11-03（日本時間）

対象：`sdmntpraustraliaeast.oaiusercontent.com`

## 判断

今回の元ZIP取得のため、クラウド環境からこのホスト1件への通信を一時的に許可する判断は妥当。ドメイン全体やインターネット全体の許可への拡大は必要としていない。設定変更はまだ確認していない。

## 確認した根拠

1. OpenAI公式ヘルプの「許可リストに追加するOpenAI/ChatGPTのドメイン」に `*.oaiusercontent.com` が掲載されている。対象ホストは正確にこのドメインの配下であり、末尾に別ドメインを付けた類似名ではない。
2. 対象URLは、ユーザーから提供されたDriveファイルに対し、認証済みGoogle Drive接続機能が返したトップレベルのファイル参照から得た。外部ページの指示や推測で作ったURLではない。
3. 参照はHTTPSで、期限と署名を持ち、読み取り用の `sp=r` が指定されていた。対象ファイルのメタデータと参照は36,372,679バイトの同名ZIPを示した。署名パラメーターの存在と読み取り指定を確認したもので、署名の暗号学的検証を行ったという主張ではない。
4. クラウド側ではプロキシのCONNECTが403で拒否された。取得先とのTLS接続・証明書の能動的検査は完了していない。TLS検証を無効にする変更は行っていない。

公式資料：
[OpenAI：WebとアプリのChatGPTエラーに関するネットワーク推奨事項](https://help.openai.com/ja-jp/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps)

公式資料はドメイン群の用途を裏付ける。個別ホストの証明書や、そこから得られる全ファイルの安全性を保証する資料としては扱わない。

## 許可の範囲と残るリスク

- ホスト許可は通常、そのホストへの通信全般を許可する。ZIP1個だけに制限する設定ではない。必要なホスト1件に限定し、取得後に不要なら設定から外す。
- 署名付きURLは、期限内に知った人がファイルへアクセスできる可能性があるため、完全なURLや署名をGitHub・Handoff・公開ログへ保存しない。
- ZIP本文は未取得。内容の安全性、SHA-256一致、展開パス、217件というファイル数は未検証。
- 取得できたら、元の指示書記載SHA-256と照合し、絶対パス・親ディレクトリへの逸脱・シンボリックリンク・重複パス等を検査して安全に展開する。実行する生成・検査コードを読んでから、今回許可された検査をクラウド内で実行する。
- ZIPの元ハッシュが一致しても、すべてのコードが無害であることまで証明するものではない。取得元・内容・実行範囲の確認を合わせて行う。
