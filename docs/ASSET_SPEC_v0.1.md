# 素材規格と少数確認 v0.1

2026-11-02。戦闘での味方左下・相手右上の配置と向きはユーザー採用済み。詳細は[BATTLE_COMPOSITION_v0.1.md](BATTLE_COMPOSITION_v0.1.md)。寸法など以下の値は量産前の**規格案**。採用原画を保存し、素材は別ファイルで制作する。設定画の生成、機械的な寸法確認、ユーザーの見た目の確認、ゲームでの検証を分ける。

## ファイルとID

- `brief/`：元資料を原形のまま保持。古い提案は現在の決定を上書きしない。
- `content/planning/`：今回の骨格・制作対象。提案を含み、そのまま戦闘エンジンへ読み込むデータではない。
- `assets/source/monsters/<species_id>/`：原画、設定画、生成元。`model_sheet_v0.1.png`など版を付ける。
- `assets/runtime/monsters/<species_id>/front.png`、`back.png`、`icon.png`：規格確認を通った取り込み用素材の予定先。未制作ファイルは空ファイルで埋めない。
- 安定IDは英小文字と数字とアンダースコア。表示名変更でIDを変えず、欠番は再利用しない。御三家には今回制作IDを予約し、既存一般種のID案は保持する。

## 画像の基準案

| 用途 | 論理ピクセル・形式 | 接地・向き・配置 | 合格の条件 |
|---|---|---|---|
| 戦闘前 | 96×96 RGBA PNG、静止1枚 | 敵側から左下へ向く3/4正面。下端中央の基準点(48,88)。四辺4px以上の透明域 | 耳・翼・尾が切れず、32pxアイコンと同一種と分かる |
| 戦闘後 | 96×96 RGBA PNG、静止1枚 | 味方側から右上へ向く3/4背面。同じ基準点 | 前面を左右反転した代用品にしない。尾と耳の裏側、器官の接続が一致 |
| 図鑑・手持ちアイコン | 32×32 RGBA PNG、静止1枚 | 顔と種固有の器官を優先、四辺2px以上の透明域 | 進化段階が見分けられる。前面の単純縮小で読めなければ描き直す |
| 人物歩行 | 1コマ32×48、全体96×192 RGBA PNG | 行は下・左・右・上、列は左足・中央・右足。基準点(16,44) | 12コマで接地点が跳ねない。全方向で同じ服と装飾 |
| 地形 | 32×32セル、RGBA PNG | 屋根・壁・地面をレイヤー分離。建物正面は下向き | 道、岸、水、角の接続。衝突データと見た目を分離 |

座標は左上原点、境界から数える。基準点は地面の接地点。大きな翼など96px枠で判別できない種が出たら、量産前に例外枠とアンカーを定義する。すべてを枠いっぱいに拡大して体格差を消さない。

既存の原画はこれらの寸法・向き・透過を満たす必要がない。**今回生成したハナミミ設定画も高解像度の参照資料であり、96pxスプライトではない。** 右向きの正面設定画を戦闘前面の完成素材として登録しない。

輪郭は濃い緑・濃い青など種の色へ寄せ、平坦な色面を中心にする。ハナミミでは緑の耳、桃色の内側、象牙色の顔、桃色のつぼみと瞳を識別点にする。アンチエイリアス付き高解像度画像を縮小しただけでピクセル絵が完成したとしない。ゲーム表示は整数倍＋nearest-neighborを候補にし、文字と操作UIは別解像度で描く。

最新のハナミミ個別候補は[HANAMIMI_SPRITES_v0.1.md](HANAMIMI_SPRITES_v0.1.md)を参照。高解像度のsource試作と、仕上げ済み寸法の候補を混同しない。

## 音の基準案

- 原本は生成サービスから得た形式のまま保管。原本WAVなどをGitへ一律に入れず、容量と保管場所を記録する。
- 取り込み候補はBGM：44.1kHz・ステレオMP3・160kbpsを出発点。必要ならOggを追加する。実機のデコードと容量で確定する。
- 効果音は短いWAVまたは対応圧縮形式を候補にし、不要なステレオ化をしない。
- BGMは90～150秒の展開を目標にし、導入部と循環部を分離できる構成を依頼する。生成指示に「loop」と書いただけでシームレスとはしない。
- ループ始終は原本サンプル位置、サンプルレート、導入部の有無を記録。MP3の遅延・末尾パディングを含め実際のデコード音で接続確認する。
- BGMの音量合わせは-18 LUFS付近、true peak -1 dBTP以下を最初の比較値とする。静かな曲も一律に押し上げない。SFXとの相対音量を実機で決める。
- 実音源未提供のため、音量・ループ・再生互換性はすべて未検証。

28曲×120秒×160kbpsならBGMだけで約67.2MB（10進）。これは容量試算で、実測ではない。全音声の初回一括取得を前提にせず、地域単位のオフライン取得・削除とセーブの保持を実装段階で設計する。
